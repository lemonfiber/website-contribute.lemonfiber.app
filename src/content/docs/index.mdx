This site is for changing lemonfiber: how a change gets in, how each repository
is built, and how the core is put together. Running lemonfiber, or building on
its API, is on [the documentation site](https://docs.lemonfiber.app).

Every page here belongs to the repository that holds what it describes, and
says at its foot which revision it was rendered from.

## The one rule

Every change cites a requirement in the
[specification](https://lemonfiber.app/spec/), and that requirement
already exists. A pull request whose `Spec:` line names an identifier the
specification does not hold is closed by `spec-check`. The rules a change
follows are specification pages:

- [Contributing](https://lemonfiber.app/spec/50-governance/contributing/):
  the rule, finding the identifier to cite, and what a commit message carries
- [Working in the repositories](https://lemonfiber.app/spec/50-governance/working-in-the-repositories/):
  claiming work, commits, opening and owning a pull request
- [Working with AI agents](https://lemonfiber.app/spec/50-governance/ai-contributors/):
  the five rules an agent keeps, and what it reads first
- [The RFC process](https://lemonfiber.app/spec/50-governance/rfc-process/):
  how a change the specification does not hold yet is proposed
- [Where an issue goes](https://lemonfiber.app/spec/50-governance/issue-routing/):
  which repository a report belongs in
